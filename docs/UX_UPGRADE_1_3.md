# PhotoSweep 1.3 実装と検証

## 実装
- 月別サークルと実際の判断率、全月選択、月ごとの再開位置。最初の月別操作で短い説明、ボタンでも仕分け可能。
- 写真30枚・動画5本の日次無料枠。既存使用記録・判断・候補・オンボーディングを保持して保存形式を移行。Proの週額／買い切りと権利を維持。
- 動画一覧、OS分類の画面収録、手動再生。サイズ確認済みの大きい順、未知のサイズは未知と表示。
- 公開PhotoKit APIによる逐次サイズ取得。サイズ計測ではiCloud原本をダウンロードしない。動画再生・圧縮は本人操作から取得。
- 削除前スナップショットと確定済み対象の結果。対象サイズと端末空き容量の測定値を分離。結果不明を成功扱い・自動再削除しない。
- Proの単発動画圧縮。最大1080p／720p、進捗・中断・比較・保存確認。保存済みの別アセットを確認した場合だけ原本を削除候補にできる。
- 別日2回の削除成果、120日間隔・版ごと1回の公式レビュー依頼。結果表示中の操作・画面離脱・バックグラウンドで予約を取り消す。

## 検証の区別
自動テストは本番の状態遷移・SQLite・UIを呼ぶが、PhotoKit／AVFoundation／StoreKitの応答は実機検証が別途必要。Webカタログはデモであり、触覚・ネイティブ追従・圧縮品質の合格証拠ではない。
検証ログは artifacts/ux13-*、最終結果は ux13-verification.json と DEVICE_TESTING.md に記録する。

## 圧縮の制約
通常のSDR動画と画面収録が対象。HDR・スローモーション・タイムラプス・シネマティック・編集済み動画は原本を保持して理由を表示する。変換結果が小さくならない場合は自動保存しない。作業容量が足りない場合は開始しない。バックグラウンドでは安全に中断し、後で再実行する。
保存結果不明のときは重複保存を防ぐため再保存・次の圧縮を止め、PhotoKitで保存IDの存在を再確認する。権限やライブラリ状況により自動復旧できない場合がある。原本は削除されない。
原本サイズは端末に存在する写真リソースのサイズであり、iCloudや「最近削除した項目」によって即時に空き容量が増えるとは限らない。

## 配布
previewはRelease・内部配布・JavaScript同梱。無料EAS枠のみ使用。商品未設定では仮価格・仮Proを表示しない。SandboxによるProと圧縮の実機検証にはApp Store Connectの商品登録が必要。ストア提出・公開は行わない。
