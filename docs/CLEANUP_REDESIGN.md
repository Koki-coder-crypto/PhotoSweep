## 採用した機能と構成
- ホーム：写真の種類を選んで一括整理。
- スワイプ：月を選択して1枚ずつ判断。続きから再開。
- 削除候補：保存済み候補の拡大・取り消し・削除。確認と削除は無料枠を消費しない。
- 設定：右上の歯車。購入の管理、通知、振動、履歴、ヘルプ。
- 写真一覧での新規選択→保存→OSの確認→成功結果。確認済みの削除は全件再取得を待たず表示から除く。
- 初回説明のカード浮遊、画面切替、選択チェックの短い拡大、スワイプ追従・速度判定、完了演出。Reduce Motionを考慮。振動は保存・成功確認後。

## ネイティブ実装
画面の見た目だけからCleanupがSwiftUI製かは判定できない。既存のExpo / React Nativeを維持し、PhotoKitによる解析をSwiftで追加した。ジェスチャーの追従・退出はReanimatedでUIスレッド上に実装。SwiftUIへの全移植は行っていない。

解析は専用のutilityキューで24枚ずつ縮小画像を取得し、dHashを算出。類似候補は撮影日時24時間以内・近い縦横比・ハミング距離を使い、代表画像と比較する。推移的に無関係な写真まで連結しない。推奨はお気に入り・解像度・コントラストを考慮する。

「同じ画像」は候補のみ原データのSHA256を8枚ずつ計算し、一致を確認する。Live Photoや編集で複数リソースを持つ画像は完全一致の対象外。類似は提案であり同一画像の保証ではない。バケット検索は保守的で、似た画像を見逃す場合がある。最終選択は利用者が行う。

原画像・ハッシュを外部へ送らない。解析時のiCloudダウンロードは無効。端末にデータがない写真や情報量の少ない画像は解析できない場合があり、対象外枚数を表示する。指紋・ダイジェストはメモリに保持し、権限・写真の変更で破棄する。再起動時は再解析する。

## 検証と残る確認
自動テストは本番の分類・無料枠・保存・削除・権利判定を呼び出す。1,000件／10,000件の解析とSQLite保存も対象。実機の速度・触覚・iCloud・OS削除確認・Sandbox購入は別の検証であり、Webの成功では合格にしない。

最初の実機確認は、削除してよいテスト写真だけを対象に、初回説明→カテゴリ→比較→1枚選択→OSでキャンセル→再選択→削除→一覧反映→強制終了後の再起動を行う。その後、スワイプ100操作、部分許可、低速通信、文字拡大、Reduce Motionを確認する。
