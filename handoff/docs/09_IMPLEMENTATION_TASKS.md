# 実装の順序と完了条件

1つずつ動線を通し、完了ログを残す。巨大な1回の変更で48画面を作り切らない。

## P0 / 保全・起動
既存指示とgit状態、実際の依存を確認。必要なら安全な作業branch。
インストール/型検査/Expo診断のbaselineを採取。既存の失敗を新規失敗と分ける。
EAS認証とiPhone起動経路を確認。未認証でも次のローカル作業は可能。
成果：baseline.md、依存整合案、実行コマンドと実際の結果。

## P1 / POP UI共通基盤
tokens、Button、Card、Chip、PhotoCard、MonthRing、PlanCard、StateView、Navigation。
全状態をfixtureで見られる開発用catalog。S03/S08/S13/S18の4画面を先に再現。
成果：4画面の比較スクショ。web previewとnativeを別表記。自動課金・写真削除なし。

## P2 / 写真の一本の動線
許可→月の写真を読む→20枚仕分け→候補確認→中断・再開。
DIでphotoRepositoryを分離、limited/denied/empty/iCloud failureを実装。
undo/skip/二重操作/保存失敗をテスト。無料枠はここで独立domainとしてテスト。
成果：S01〜S14、S37〜S39/S45の主状態が動く。

## P3 / 本当の削除と記録
OS確認、削除job保存、結果照合、キャンセル/失敗/再起動復旧。
テスト用写真だけを使い、本人の確認を経て実機検証。
成果：S15/S16/S40、記録36、候補0/全部残す、保存状態の証拠。

## P4 / 課金
商品/資格/価格取得→透明なPaywall→正規購入→権利更新→復元→管理/取消→失効。
legacy lifetime分岐を必要に応じて残す。isProのみ/日付+7日の擬似権利を禁止。
価格不明、対象外、pending、UserCancelled、確認失敗、通信断、grace、返金を区別。
成果：S17〜S32/S46〜S48とバリアント。Sandbox結果が揃うまで課金完了扱いにしない。

## P5 / 気持ちよさ・細部
動き、触覚、写真の先読み、アクセシビリティ、日本語、通知(任意)、ヘルプ、規約。
重い演出なし。写真を消さず全部残しても完了感。候補確認をpaywallで遮らない。
成果：48状態のテスト用catalogとスクショ。ユーザー写真を含めない。

## P6 / 公開候補
検証、Releaseでfixture経路を無効、ストアの実情報、公開URL、秘密なし。
TestFlight用build/提出の準備。ただし有料クラウド実行・提出・公開はユーザー承認後。
成果：buildID/ログ/実機checklist/未完了を明示。検証未実施なら公開しない。

## 中断後の再開
各phase後にアプリ側の `docs/implementation-status.md` へ記録。
現在phase、branch、commit、変更ファイル、実行済チェック、失敗、blocked、次の最小動線。
1つの阻害要因で無関係な実装まで全部停止しない。認証が必要な部分だけblockedとして進める。

## オーナーへの質問を絞る

実商品・公開設定・実機アクセス・有料枠・秘密認証・データ削除・公開に必要なものだけまとめて聞く。
